## Why this matters

`bun audit` reports five advisories against the pinned Astro version, including
one HIGH: a host-header SSRF in the prerendered error-page fetch
(GHSA-2pvr-wf23-7pc7). The practical exposure on this site is limited — it is a
fully static build with no server code, served as assets by a Cloudflare Worker
— but the fix is a patch bump inside the 6.x line with no API changes, and
GitHub is surfacing the vulnerability publicly on a repository attached to the
owner's name. For a portfolio whose pitch is engineering judgment, a visible
unpatched HIGH advisory is its own kind of cost. This takes minutes and clears
the badge.

## Steps

### Step 1 — Capture the baseline

Before changing anything, record the current state so the reviewer can compare:

```bash
bun install
bun run build
bun audit 2>&1 | tee /tmp/audit-before.txt
grep -c "GHSA-2pvr-wf23-7pc7" /tmp/audit-before.txt   # expected: 1
```

Also snapshot the built output so you can prove the upgrade changed nothing
visible:

```bash
shasum dist/index.html dist/404.html
```

Record both hashes in your NOTES.

### Step 2 — Bump Astro to 6.4.8

```bash
bun add astro@6.4.8
```

Confirm the pin landed:

```bash
grep '"astro"' package.json          # expected: "astro": "^6.4.8"
bun pm ls | grep -w astro            # expected: astro@6.4.8
```

### Step 3 — Confirm the advisories cleared

```bash
bun audit 2>&1 | tee /tmp/audit-after.txt
grep -c "GHSA-2pvr-wf23-7pc7" /tmp/audit-after.txt    # expected: 0
```

The `postcss`, `sharp`, and `undici` blocks may still appear — that is expected
and in scope for nobody. Only the `astro` block must be gone.

### Step 4 — Verify the site is unchanged

```bash
bun run check    # exit 0, 0 errors
bun run lint     # exit 0
bun run build    # exit 0, "2 page(s) built"
```

Then confirm the rendered output is materially identical:

```bash
shasum dist/index.html dist/404.html
```

Compare to the step 1 hashes. **They may differ** — Astro patch releases can
change asset hashes or minification details. That is acceptable. What must hold
is that the content is intact:

```bash
grep -c "I build the systems that let agents ship real software" dist/index.html  # expected: 1
grep -c "eggers.dev" dist/index.html      # expected: >= 1
grep -c "brendan@eggers.dev" dist/index.html  # expected: >= 1
ls dist/                                   # expected: index.html, 404.html, _astro/, favicon.svg, og.png, robots.txt, sitemap-0.xml, sitemap-index.xml
```

If any of those content checks fails, STOP — the upgrade broke rendering.

### Step 5 — Confirm the diff is only the two dependency files

```bash
git status --short
```

**Expected**: exactly `M package.json` and `M bun.lock`. Anything else is a
scope violation.
